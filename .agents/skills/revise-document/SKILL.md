# 文書の添削

目的は、明日のユーザーが見出しと段落の1文目だけを読んで、話の筋をつかめることである。
文の言い回しの決まりは`.claude/rules/writing-style.md`にある。このスキルは、その上で段落と番号の扱いを直す。

## 直さないもの

`.claude/rules/writing-style.md`の「直すときは意味を変えない」に従う。決めた中身、条件、数値、言い切りの強さは変えない。消してよいのは、同じことの言い直しと、別の節にすでに書いたことだけである。

## 手順

1. 長い行と、番号だけで出てくる言葉を数える。

   ```bash
   f=docs/designs/<feature-name>.md
   # 表の行を除いて、200字を超える行（awkはバイトで数えるので、perlで字を数える）
   perl -CSD -Mutf8 -ne 'chomp; print "$.: ", length($_), "字\n" if length($_) > 200 && !/^\|/' "$f"
   # 表の行を除いて、言葉の後の括弧の外に出てくる番号（E2Eのような言葉も拾うので、目で見て外す）
   perl -CSD -Mutf8 -ne 'print "$.: $_" if !/^\|/ && /(^|[^（(、〜A-Za-z0-9-])(S|F|E|B|P|AC|R)-?[0-9]+[a-z]?/' "$f"
   ```

2. 1つの段落か箇条書きの1項目に、言いたいことが2つ以上あれば分ける。目安は、1段落3文まで、1項目200字まで。分けられないときは、表にするか、「細かい決まり」の小見出しを立てて下に回す。
3. 段落の1文目に、その段落の結論を書く。理由・例外・列の名前は2文目より後に置く。
4. 番号は、言葉のあとに括弧で添える。画面は「はじめの登録の画面（S-24）」、要件は「招待を通らない登録の例外（F-03）」と書く。番号だけを主語や目的語にしない。同じ節で2回目からは、言葉だけにしてよい。表の「要件」の列のように、番号を並べるための場所では番号だけでよい。
5. 本文で流れを書き、列の名前・値・境界の値は表にまとめる。本文の1文に、列名やAPIのパスを3つ以上入れない。
6. 理由は1つの文で書き、根拠の文書は括弧で添える。同じ理由を節ごとに書き直さない。
7. 見出しだけを上から読み、話が通るかを確かめる。通らなければ見出しを中身の言葉に直す。
8. 手順1のコマンドをもう一度流し、残った長い行が表の行か、分けられない理由があるものだけになったことを確かめる。

## 直した例

| 直す前 | 直したあと |
| --- | --- |
| S-24は、合言葉の欄と、オーナーがいないときだけグループの名前と表示名の欄を出す。 | はじめの登録の画面（S-24）には、合言葉の欄を出す。オーナーがまだいないときだけ、グループの名前と表示名の欄も出す。 |
| 札を出すとき、`recovery_links.ticket_issued_at`が空なら時刻を書く。すでに入っていれば書き換えず、最初の札の時刻を保つ。札を出し直しても…（1項目に4つの決まり） | 1項目に1つの決まりにし、列の扱いは表に移す |

## 終わったら

PRの「確かめたこと」に、手順1のコマンドで数えた長い行の数（直す前と後）を書く。
