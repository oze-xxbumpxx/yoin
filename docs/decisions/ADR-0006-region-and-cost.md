# ADR-0006リージョンと費用

- 状態：提案（2026-11-22）。決定1・3・4は同日に大関が確認のページで選んだ（どれも推奨どおり。決定4は1回目に無料プランを選び、費用の見込みを聞いて有料プランに直した）。決定2・5・6・7は仮に決めたもので、マージまでに異議が無ければ確定する
- 決めた人：大関
- 関連：[AWS構成](../architecture.md)、[ADR-0002](ADR-0002-schema-and-functions.md)、[ADR-0004](ADR-0004-dev-tools.md)、[データモデル](../data-model.md)、[論点の記録](../discussions/cost-and-region.md)

## 背景

AWS構成では、リージョンを東京にすると決めていた（AWS構成のC-2）。しかしNeonには東京のリージョンが無く、アジアにあるのはシンガポールとシドニーだけである（https://neon.com/docs/introduction/regions ）。NeonのプロジェクトとCognitoのユーザープールは、作ったあとでリージョンを変えられない。実装は土台も含めてDevinに渡すので、渡す前にリージョンを決める。

あわせて、工程6に回していた3つを決める。DBのバックアップの保持期間（データモデル「決めないこと」）、AWSアカウントのプラン（PR/FAQの内部FAQ）、費用と流量の上限（AWS構成とADR-0005の「決めないこと」）である。

決める前からあった前提は次のとおり。

- 利用者は招待制で、1年後も10人以下。費用は無料の範囲に収めるのが目標（PR/FAQ）。
- 書き込みは1つのトランザクションで行い、最初にグループの行を`FOR SHARE`でロックする（ADR-0002の決定3）。Lambdaは要求ごとにNeonへWebSocketでつなぎ、終わったら切る（ADR-0004の決定4、AWS構成のA-1）。
- ClaudeとDevinはAWSとNeonにつながない（`AGENTS.md`の「コマンドの範囲」）。

## 決定

### 1.AWSの資源もNeonも、シンガポールに置く

AWSのリージョンはアジアパシフィック（シンガポール）`ap-southeast-1`にする。Neonのプロジェクトも`aws-ap-southeast-1`に作る。CloudFrontは世界の拠点から配るので、リージョンを持たない。

1回の書き込みでは、LambdaとNeonのあいだを何度も往復する。WebSocketでつなぐ、BEGIN、グループの行の`FOR SHARE`、読む、書く、読み直す、COMMITの順である。端末とAPIのあいだは、要求ごとに1往復しかしない。東京とシンガポールの往復は約70msなので（第三者の集計。https://www.economize.cloud/resources/aws/latency/ap-northeast-1-vs-ap-southeast-1/ ）、往復の多いLambdaとNeonを近くに置くほうが速い。AWSを東京に置くと、書き込み1回で数百msの待ちが増える見込みである。

DBは、どちらに置いてもシンガポールにある。AWSを東京に残す案と比べると、この決定ではCognitoのユーザープール（メールアドレスなど）とグッズの画像もシンガポールに置くことになる。外部FAQには、データをシンガポールのサーバーに置くことを書く。

待ち時間はまだ測っていない。測るスクリプトは、リポジトリの外（claude.aiのプロジェクトのファイルの`step6/measure-neon.mjs`）に置いてある。Neonの本番のプロジェクトを作ったあとで大関がMacから流せば、この決定の数字を確かめられる。

### 2.Terraformの状態ファイルのバケットも、シンガポールに置く

ADR-0004の決定5で、状態ファイルのバケットは東京に置くと書いた。これを、ほかのAWSの資源と同じシンガポールに変える。リージョンを1つにそろえると、Devinに渡すTerraformの設定とIAMの権限が単純になる。

### 3.DBを過去の時点に戻せる期間は、Neonの無料プランの6時間にする

Neonの無料プランは、6時間以内（変更が1GBまで）の任意の時点に戻せる（https://neon.com/pricing ）。写しを別に取る仕組みは作らない。6時間は、yoinがDBを戻せる期間である。これとは別に、Neonは自分のバックアップを30日残す（https://neon.com/docs/security/security-overview ）。外部FAQには「データベースを戻せる期間は、削除が終わってから6時間です。データベースの提供元（Neon）のバックアップには、最大30日残ります」と書く。退会を受け付けたあと、`erasure-worker`が非同期で行を消すので、起点は受付でなく削除が終わった時点になる。

10人の招待制なので、DBを壊したら6時間以内に気づける見込みである。マイグレーションは、試験とE2Eを通してから流す（ADR-0004の決定3）。

### 4.AWSアカウントは新しく作り、最初から有料プランにする

2025年7月からの新しいアカウントには、無料プランと有料プランがある。無料プランは6か月かクレジットを使い切った時点で終わり、有料プランに移らないとアカウントが閉じられる（https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/free-tier-plans.html ）。有料プランでも、作ったときのクレジット（100ドル、条件を満たすと最大200ドル）と、常時無料の枠は使える。費用は月に数円の見込みなので、移し忘れてリマインドが止まる心配を無くすほうを選ぶ。

### 5.費用はAWS Budgetsのメールで見張り、Neonの使った量は月に1回見る

AWS Budgetsで月5ドルの予算を1つ作り、実績が超えたときと、予測が超えそうなときにメールを送る。予算はTerraformで書く。通知だけの予算は無料である（https://aws.amazon.com/aws-cost-management/aws-budgets/pricing ）。

Neonの計算時間は、大関がコンソールで月に1回見る。見込みは無料の上限の2割ほどで、超えそうになるのは使い方が変わったときか、不具合でNeonを起こし続けたときだけである。不具合でNeonが止まると、リマインドの送信が失敗し、AWS構成のC-4のアラームが知らせる。

### 6.API Gatewayのステージの流量の上限を、毎秒20回、瞬間40回にする

画面の不具合で要求が止まらなくなったときに、瞬間の暴走を抑える。10人が同時に画面を開いても、この上限には届かない。E2Eを並べて流して上限に当たったら、値を見直す。

この上限で守れるのは、費用の増え方を1日に約5ドルまでにすることだけである。上限いっぱいの毎秒20回は1日に約173万回で、API Gatewayに約2ドル、Lambdaに約3ドルかかる（Lambdaは512MB・1回0.2秒と仮定。月100万回と40万GB秒の無料枠はすぐに使い切る）。1か月暴走すると約160ドルになる。この上限もAWSは「保証された上限ではなく目標」としているので（https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-throttling.html ）、費用の上限としては扱わない。Neonの計算時間は守れない。Neonは5分使われないと止まるので、5分に1回の要求でも起きたままになり、月に約180 CU時間を使って無料の100 CU時間を超える。

### 7.要求の数が増えたら、CloudWatchのアラームで1時間以内に知らせる

API Gatewayの要求の数と、Lambda `notification-sender`の起動の数に、1時間ごとのアラームを置く。決めた数を超えたら、C-4と同じメールで知らせる。値は、ふだんの数の10倍ほどを目安に、最初の1本の設計で決める。アラームは月10個まで無料で、定期に動く関数を増やさずに済む（2026-11-22、レビューの指摘を受けた仮決定）。

決定5のBudgetsはメールを送るだけで、更新も1日に数回なので、暴走に気づくのが約2日あとになる。不具合で画面やリマインドの予約がNeonを起こし続けると、Neonの計算時間を使い切る前に、このアラームで気づける。

## 費用の試算

10人が1日に30回ずつ操作したときの、月の費用の推測である。1ドル150円で計算した。API GatewayとS3の単価は、AWSが公開している料金の一覧のデータ（シンガポール。https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonApiGateway/current/ap-southeast-1/index.json とS3の同じ形のURL）で確かめた。

| サービス | 見込んだ使い方 | 月の費用 |
|---|---|---|
| API Gateway HTTP API | 月に約9,000回。100万回あたり1.25ドル | 約0.01ドル（約2円） |
| S3（グッズの画像） | 300KBの画像を200枚置き、月に約15,000回見る。保存は1GB月0.025ドル | 約0.01ドル（約1円） |
| Lambda | 月100万回と40万GB秒まで無料 | 0円 |
| EventBridge Scheduler | 月1,400万回まで無料 | 0円 |
| SQS、CloudWatch（ログ月5GB、アラーム10個）、SSMの標準のパラメーター、外への転送（月100GB） | 無料の枠に収まる | 0円 |
| Cognito | 月1万MAUまで無料で、期限が無い | 0円 |
| Neon | 1日に20回起きて1回7分動くと、最小の大きさ（0.25 CU）で月に約18 CU時間。無料は100 CU時間。ただし、同じ1日300回の操作が16時間に均等に散ると、5分より短い間隔で起こし続けるので、月に約120 CU時間になる | 0円（散り方によっては無料の上限を超える） |
| 合計 | | 約3円（消費税を足して約3.3円）。クレジットがあるあいだは0円 |

費用が増えるのは、次の3つのときである。

- 不具合で要求が止まらなくなったとき。API Gatewayは100万回で約190円かかる。Lambdaも同じ回数だけ動く。決定6の上限で1日約5ドルまでに抑え、決定7のアラームで1時間以内に知らせる。止めるのは人が行う。
- 不具合でNeonを5分より短い間隔で起こし続けたとき。止まらずに動くと月に約180 CU時間になり、無料の100 CU時間を超える。無料プランでは請求は来ず、次の月までDBにつながらなくなる。
- 独自ドメインを使うとき（まだ決めていない）。Route 53に月約75円と、ドメインに年1,500〜2,000円がかかる。

## 選ばなかった案

詳しい利点と欠点は[論点の記録](../discussions/cost-and-region.md)にある。

- AWSは東京に置き、Neonだけシンガポールに置く。書き込み1回ごとに往復が増え、そのたびに約70msずつ待ちが増える。
- 東京に集約し、DBをAurora DSQL（東京）に替える。行のロックは`FOR UPDATE`と`FOR KEY SHARE`だけで、グループの行の`FOR SHARE`が使えない。ロックで待たせずCOMMITで衝突を見つけてやり直す作りなので、ADR-0002〜0005の書き込みの順番とマイグレーションの手順を作り直すことになる。
- 東京に集約し、DBをSupabase（東京）の有料プランに替える。月25ドルからかかる。無料プランは1週間使わないと止まり、手で起こすまでリマインドが届かない。
- DBを戻せる期間を延ばす（Neonの有料のLaunchプランで7日、または毎日の`pg_dump`の写しを7日）。退会した人のデータが7日残る。Launchプランは月に約2ドルかかる。
- AWSアカウントを無料プランで作る。6か月で終わり、移し忘れるとアカウントが止まり、リマインドも止まる。

## 結果

### 良くなること


- 書き込みの待ちが、端末とAPIのあいだの1往復の分で済む。
- 費用は月に数円で、無料の範囲に収めるという目標をほぼ満たす。
- AWSの資源のリージョンが1つにそろう。

### 悪くなること・残るリスク


- 読むだけの軽い要求でも、端末とAPIのあいだで毎回約70msかかる。画像もシンガポールのS3から届き、ログインもCognitoとの往復ごとに約70msかかる。
- 待ち時間の数字はまだ測っていない。測った数字が見込みより大きく違っても、NeonとCognitoを作ったあとではリージョンを変えられない。
- DBを戻すと、戻した時点より後に解散・退会・外すで消したデータも戻る。消し終えた記録は最後の段で行ごと消すので（データモデルのR17）、何を消し直すかは記録からわからない。戻せる期間が6時間なので、消し直すのはその6時間の分だけになる。戻すときの手順は、最初の1本の設計で決める。
- Neonの計算時間を使い切ると、次の月までDBにつながらない。月に1回、手で見るだけなので、決定7のアラームに当たらない形で増えたときは、C-4のアラームで初めて気づく。

## 移行・戻し方

対象外。まだAWSの資源もNeonのプロジェクトも作っていない。

## この決定では決めないこと

- 独自ドメインを使うか（公開前）。使うなら、CloudFrontの証明書は`us-east-1`に作る
- DBを戻すときの手順と、戻したあとに消し直す方法（最初の1本の設計）。DBを戻しても、Schedulerの予約・Cognitoの利用者・S3の画像は戻らないので、戻った申込に予約が無くリマインドが届かない、といった食い違いも扱う
- AWS構成の図（`docs/images/aws-architecture.svg`）に、リージョンの名前とSQS・アラームを描き足すこと（最初の1本の設計の前）
