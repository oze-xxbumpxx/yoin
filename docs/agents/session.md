# 作業の進め方

もとはリポジトリ直下の`AGENTS.md`の「作業の進め方」。中身は移しただけで、決まりは変えていない。

## 作業の進め方

1. 作業開始時に`git status`と`logs/`の最新ログを読み、実装済み・未完了を確かめる。
2. `.claude/skills/classify-change/SKILL.md`で変更規模を判断する。判定結果に **ユーザー承認: 必要 / 不要** を含める。L2 / L3の要件定義書・設計書は、書く前に`.claude/skills/ask-questions/SKILL.md`の手順で問いを出し、答えを受けてから書く。要件にはF-（機能）・E-（異常系）・B-（境界）の番号を振り、満たすユーザーストーリーを冒頭に書く。
3. 小さな修正は直接進める。ユーザーが既に依頼した範囲で再承認を求めない。
4. 品質コマンドは実在するものだけ実行し、未導入のゲートは`unknown`と報告する。
5. 人が読む文章（報告・ログ・docs・Issue・PR・コメント）は`.claude/rules/writing-style.md`の書き方にする。
6. 作業の終わりと、設計の工程を閉じたときに、変更・検証・未完了事項を`logs/YYYY-MM-DD.md`に記録する。
7. ハーネス構成（`.claude/` / `.agents/` / `AGENTS.md`）の変更はPRで重点レビューする。
