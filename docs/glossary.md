# 用語集

状態：確定（2026-11-03）。属する文脈は文脈マップで確定（2026-11-05）。データモデルで「グループは1人でもよい」と決め、自分用グループを追加（2026-11-06）。レビュー対応でオーナー、退会、解散、リマインドの定義を更新（2026-11-07）。

英語名はコードの命名にそのまま使う。

## グループ（`group`）

グループ、メンバー、招待。2026-11-05に「共有」から改名

| 用語 | 英語名 | 定義 |
|---|---|---|
| ユーザー | `User` | yoinに登録した人。招待リンクから最小限の登録をすると、ユーザーになる |
| グループ | `Group` | いつもの仲間で作る1つの集まり。1人だけでもよい。複数の公演を入れ、公演の情報、チケット、グッズ、記録を共有する。公演ごとに誰が行くかは「参戦」で表す |
| 自分用グループ | `PersonalGroup` | ユーザー登録のときに自動で作る、本人だけのグループ。1人で行く公演を記録する。招待リンクは出せず、解散もできない。退会のときに消す |
| メンバー | `Member` | グループに参加しているユーザー |
| オーナー | `Owner` | グループを管理するメンバー。最初はグループを作った人で、退会のときは一番前から参加しているメンバーに引き継ぐ。招待リンクの発行と、グループの解散ができる |
| 招待リンク | `InviteLink` | グループに参加するためのURL。有効期限と利用回数の上限を持つ |
| 退会 | `Withdrawal` | ユーザーがyoinをやめること。本人だけのデータ（アカウント、参戦と記録、本人が申込者の申込、頼まれ物、下書き、通知）はすべてすぐに削除する。公演やセトリなどグループの全員のデータは残す |
| 解散 | `Disband` | オーナーがグループをなくすこと。グループのデータは削除し、過去の公演の参戦には公演とセトリの写しを残す。これからの公演の参戦は消す |

## 公演カタログ（`catalog`）

アーティスト、ツアー、公演、会場、セトリ

| 用語 | 英語名 | 定義 |
|---|---|---|
| アーティスト | `Artist` | 公演を行う演者。グループ内で名前を登録する |
| ツアー | `Tour` | 同じ名前で行われる公演のまとまり。ツアー名、グッズの販売時間など、公演に共通する情報を持つ。公演はツアーに属さなくてもよい（単発の公演、フェスなど） |
| 公演 | `Concert` | 決まった日時に、決まった会場で行われる1回のライブ。開場時刻、開演時刻、公式サイトのURLを持つ |
| 会場 | `Venue` | 公演が行われる場所。最寄り駅とメモを持ち、次の公演でも選び直せる |
| セトリ | `Setlist` | 公演で演奏された曲の順番付きの一覧。公演に属し、グループの誰が入力しても全員に同じものが見える |
| 曲目 | `SetlistItem` | セトリの1行。MVP1では曲名を文字列のまま持つ |
| 下書き | `Draft` | 確定前の登録内容。公演は「下書きを作る → 確認して確定する」の2段階で登録する。公演カタログとグッズがそれぞれ自分の下書きを持つ。MVP2の自動入力も、各文脈の「下書きを作る」窓口を呼ぶ |

## 参戦記録（`attendance`）

参戦した本人が残す記録

| 用語 | 英語名 | 定義 |
|---|---|---|
| 参戦 | `Attendance` | メンバーが公演に行くこと。行く予定の段階から参戦と呼び、行ったかどうかは参戦記録があるかで区別する |
| 参戦記録 | `AttendanceRecord` | 参戦した本人が公演の後に残す記録。座席、同行者、ひとことを持つ |
| 座席 | `Seat` | 参戦記録に書く席の情報。ブロック、列、番号などを自由に書く |
| 同行者 | `Companion` | 同じ公演に一緒に行く人。グループのメンバーか、yoinを使っていない人の名前。他人の名前なので、グループ解散時と、その人の退会時は人数表示に置き換える |
| 公演の写し | `ConcertSnapshot` | 解散のときに参戦記録に残す、公演、アーティスト名、セトリの写し。公演カタログの公演とは別のもの |

## チケット（`ticket`）

申込から受取までの状態と期限

| 用語 | 英語名 | 定義 |
|---|---|---|
| チケット申込 | `TicketApplication` | チケットを取るための1回の申込。枚数、受取方法、結果発表日時、入金期限、受取開始日時と、申込から参戦までの状態を持つ |
| 申込者 | `Applicant` | チケット申込をしたメンバー。入金と受取をする人で、リマインドの宛先になる |
| 当落 | `LotteryResult` | 抽選の結果。当選か落選か |
| 入金期限 | `PaymentDeadline` | 当選後に代金を払う期限。過ぎると申込は無効になる |
| 受取 | `Pickup` | チケットを手元に用意すること。コンビニで発券するか、スマチケをダウンロードする |
| 受取方法 | `PickupMethod` | コンビニ発券かスマチケか |
| 受取開始日時 | `PickupStartsAt` | 受取ができるようになる日時。受取できるかどうかは状態として保存せず、この日時と現在時刻から計算する |
| 分配 | `Distribution` | スマチケを同行者に1枚ずつ渡すこと。チケット申込のうち、誰の分の何枚目かを決める割当ごとに持つ |

## グッズ（`merch`）

買う物と分担

| 用語 | 英語名 | 定義 |
|---|---|---|
| グッズ | `MerchItem` | ツアーや公演で売られる品目。品名、価格、画像を持つ。ツアーに属し、ツアーがない公演では公演に属する。画像はユーザーが撮った写真かスクショ |
| グッズリスト | `MerchList` | 公演ごとに、誰が何をいくつ買うかをまとめた一覧。品目そのものはツアー（ツアーがなければ公演）に属する |
| 下書き | `Draft` | 確定前の品目。「下書きを作る → 確認して確定する」の2段階で登録する。公演カタログの下書きとは別に持つ |
| 購入担当 | `Buyer` | その品目を当日買いに行くメンバー |
| 頼まれ物 | `MerchRequest` | 他のメンバーから買うよう頼まれた品目と数。頼んだ人と購入担当を持つ |

## 通知（`notification`）

期限のリマインド

| 用語 | 英語名 | 定義 |
|---|---|---|
| リマインド | `Reminder` | 期限を知らせる通知。結果発表と受取開始はその時刻に、入金期限は前日の20時と締切の3時間前に届ける。チケットが通知に送信を予約する。チケットのリマインドは申込者だけに送る |
| 通知先 | `PushSubscription` | Web Pushを受け取る端末の登録。iPhoneはホーム画面に追加したときだけ登録できる |

## 決めたこと（2026-11-03）

- Q1グループの単位：いつもの仲間で1つ（複数の公演を入れる）
- Q2チケットの申込と、当選後のチケットを分けるか：1つの「チケット申込」が状態を持つ
- Q3「参戦」をいつから使うか：行く予定の段階から「参戦」
- Q4同行者にアプリを使っていない人を含めるか：アプリを使っていない人も名前で記録できる
- Q5ツアーのない単発の公演：ツアーなしの公演を許す
- Q6グッズリストの単位：品目はツアー、買う分担は公演ごと
- Q7「公演」の英語名：Concert

## 文脈マップで決めたこと（2026-11-05）

- 「共有」の文脈を「グループ」に改名
- 下書きは公演カタログとグッズがそれぞれ持つ
- 申込者（`Applicant`）と公演の写し（`ConcertSnapshot`）を追加
- 退会した人が同行者になっていたら、人数表示に置き換える
- チケットのリマインドは申込者だけに送る

## データモデルで決めたこと（2026-11-06）

- グループは1人でもよい。1人で行く公演も記録できるようにするため
- ユーザー登録のときに、自分用グループ（`PersonalGroup`）を自動で作る。データでは`groups.kind = personal`で表す

## レビュー対応で決めたこと（2026-11-07）

- オーナーは「グループを作った人」から「グループを管理するメンバー」に定義を変える（退会で引き継ぐため）
- 退会で消すのは本人だけのデータ。グループの全員のデータは残す
- 解散で残すのは過去の公演の参戦。これからの予定は消す
- リマインドは期限の種類ごとに決めた時刻に届ける
