## プレスリリース

### yoin、ライブという非日常の一日を、仲間と一緒に残せるアプリをプレリリース

終演後のセトリと参戦記録から、当日までのチケットとグッズの準備まで、公演ごとに同行者と共有できる

**2027年1月（プレリリース）**　ライブは、日常から離れた特別な一日です。けれど、どの曲が演奏されたか、どの席から見たか、誰と行ったかは、日がたつにつれて少しずつ薄れていきます。その日を迎えるまでにも、チケットの発券やグッズの分担といった細かな準備に追われます。

yoinは、いつもライブに一緒に行く仲間でグループを作り、公演ごとにその一日を記録として残し、そこに至るまでの準備も分け合えるWebアプリです。iPhoneでもAndroidでも、ブラウザからホーム画面に追加して使えます。

- 記録：公演が終わったらセトリを入力し、座席、同行者、ひとことを残せます。アプリを使い始める前の公演も、さかのぼって登録できます。
- グッズ：公式のグッズ一覧の写真を品目に付けて、誰が何をいくつ買うかを分担できます。頼まれ物と合計金額もひと目でわかります。
- チケット：申込から発券までの状態と期限をまとめて管理し、結果発表、受取開始、入金期限を、間に合う時刻に通知します。

開発者の大関宏士朗は次のように話しています。「ライブは非日常の空間で、そのいっときを忘れたくないと思っています。けれど実際には、準備に追われて当日を迎え、終わった後の記憶は日に日に薄れていきました。yoinは、準備を仲間と分け合い、その一日をあとから思い出せるように作りました。」

yoinは招待制です。グループを作った人が招待リンクを送り、受け取った同行者は最小限の登録で参加できます。

## 外部FAQ

**Q. 誰が使えますか。**
招待制です。グループを作った人から招待リンクを受け取った人だけが参加できます。

**Q. 同行者もアカウントを作る必要がありますか。**
招待リンクから、最小限の登録で参加できます。

**Q. どのアーティストのライブでも使えますか。**
使えます。公演情報は、グループ内の誰かが手入力で登録します。登録した公演はグループのメンバー全員に見えます。

**Q. 公演情報は自動で入りますか。**
プレリリースの時点では入りません。手入力ですが、ツアー単位でまとめて登録でき、一度登録した会場は次の公演でも選べます。詳しい情報は、公演に貼った公式サイトのURLから確認します。自動での取り込みは次のバージョンで追加する予定です。

**Q. 通知はいつ届きますか。**
結果発表と受取開始は、その時刻に届きます。入金期限は、前日の20時と締切の3時間前に届きます。iPhoneでは、yoinをホーム画面に追加した場合だけ通知を受け取れます。

**Q. グッズの画像は誰が見られますか。**
同じグループのメンバーだけです。外部には公開しません。

**Q. チケットを譲ったり売ったりできますか。**
できません。yoinはチケットの売買や譲渡を仲介しません。

**Q. 退会するとデータはどうなりますか。**
あなただけのデータ（アカウント、参戦記録、申し込んだチケット、頼んだグッズ、通知の設定）をすべてすぐに削除します。グループで共有している公演、セトリ、グッズはグループに残ります。データベースのバックアップからは、保持期間が過ぎると消えます。

**Q. グループを解散するとどうなりますか。**
メンバー一覧、招待リンク、チケット、グッズの画像と頼まれ物はすぐに削除します。公演とセトリはグループからは消えますが、過去の公演については各メンバーの参戦記録に写しが残ります。これからの公演の予定は消えます。記録に書かれた同行者の名前は消え、「同行者2名」のように人数だけが残ります。

**Q. 料金はかかりますか。**
かかりません。

## 内部FAQ

**Q. なぜ作るのか。**
本人がライブに行くときの困りごとが4つあるためです。グッズの写真と買う物が結びつかない、発券を忘れる、ツアーや会場の情報を毎回サイトで探す、セトリや過去のライブを残しておけない、の4つです。あわせて、Cookpitとtomotabiにない技術要素（時刻起動の通知、画像の保存、Web Push、IaC）を見せるポートフォリオにします。

**Q. 月額コストはいくらか。**
見込みは0円から数十円です。招待制で利用者は10人以下のため、Lambda、EventBridge Scheduler、Cognitoは常時無料の枠に収まる見込みです。S3は新規アカウントでは常時無料の対象外なので、画像の量に応じて少額の料金が出る可能性があります。Neonは無料プランの範囲で使う想定です。どの数値も工程6でAWSとNeonの公式の料金ページをもとに試算して確定します。

**Q. AWSアカウントはどうするか。**
新しく作ります。無料プランは6か月後かクレジットを使い切った時点で閉鎖されるため、長く運用するなら有料プランを選び、常時無料の範囲で動かします。工程6の前に決めます。

**Q. なぜネイティブアプリにしないのか。**
PWAならiPhoneとAndroidを1つのコードで扱えるためです。代わりに、iPhoneではホーム画面に追加しないと通知が届かないという制約を受け入れます。初回の案内画面でホーム画面への追加を促します。

**Q. 主なリスクは何か。**

| リスク | 対策 |
|---|---|
| iPhoneの同行者がホーム画面に追加せず、通知が届かない | 初回の案内画面で追加を促す。通知が届かない状態を画面上で示す |
| 招待リンクが意図しない人に渡る | リンクに有効期限と利用回数の上限を設ける |
| 公式のグッズ画像の扱い | グループ内でだけ表示し、公開や再配布はしない |
| プロダクト名が既存のサービスと重なる | 公開前にApp Storeと商標データベースで確認する |
| 2027年1月のプレリリースに間に合わない | 対策は未定。日程と、遅れたときに後ろへ回す順番を決めて書く |

**Q. セトリの曲はどう持つか。**
MVPでは曲名を文字列のまま持ちます。「この曲を生で聴いた回数」の集計に必要な曲マスタは、MVP2以降で作ります。

## 付録

### MVPの範囲

1.ツアー・公演・会場の登録（グループ内で共有、過去の公演も登録できる）
2.セトリの手入力（公演ごとの曲順リスト）
3.参戦記録（座席、同行者、ひとことメモ）
4.チケットの状態管理と、受取開始日・入金期限のリマインド
5.グッズリスト（画像付きの品目、購入担当、頼まれ物、合計金額）
6.同行者の招待

### やらないこと（MVP）

- チケットの売買・譲渡の仲介
- ツアー情報とグッズ情報の自動取得（MVP2で入れる）
- LLMによる告知文やグッズ画像の取り込み（MVP2で入れる）
- ファン同士のSNS機能
- オフライン対応
- ネイティブアプリ
- 決済・割り勘の精算

### 非機能要件

| 項目 | 要件 |
|---|---|
| 公開範囲 | 招待制。本人と同行者だけが使う |
| 規模 | 1年後に10人以下 |
| 端末 | iPhoneとAndroidが半々。PWAとしてブラウザで動かす |
| 通知の時刻 | 期限の種類ごとに決めた時刻に届ける。結果発表と受取開始はその時刻、入金期限は前日の20時と締切の3時間前（2026-11-07に「当日中」から変更） |
| 退会 | 本人だけのデータをすべてすぐに削除する。グループの全員のデータ（公演、セトリ、確定したグッズ）は残す |
| グループ解散 | データの持ち主ごとに扱う。グループのデータ（メンバー一覧、招待リンク、チケット、グッズ）はすぐ削除する。過去の公演の公演とセトリは各メンバーの参戦記録に写しを残し、これからの公演の参戦は消す。本人の参戦記録は本人に残し、同行者名は人数表示に置き換える |
| 画像 | グループのメンバーだけが見られる |
| コスト | AWSとNeonの無料枠に収めることを目指す。基準は工程6で決める |

### 決定事項（2026-11-02）

- 2027年1月のプレリリースではMVP1（上の6機能）を出す。1月は目標として扱い、設計を削って間に合わせることはしない。
- グループ解散時のデータは持ち主ごとに扱う（非機能要件を参照）。
- プレスリリースは記録を前面に置く。
- MVP1ではツアー情報とグッズ情報を手入力で登録する。自動取得はMVP2で入れる。そのため、公演とグッズの登録は「下書きを作る → 確認して確定する」の2段階にしておき、MVP2で取り込み処理を同じ入口に差し込めるようにする。

### MVP2で決めること

- 自動取得の方式。候補は「URLを貼って取り込む」方式（ユーザーが貼った告知ページを1回だけ読み、LLMで下書きにする）。
- グッズ画像の扱い。現時点の方針案は、品名と価格の文字情報だけを取り込み、画像はユーザーが撮った写真かスクショを付ける形。
- 取り込み先のサイトの利用規約の確認。
