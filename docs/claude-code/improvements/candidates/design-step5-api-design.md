## 観測した事象

### 事象1: 送り直しと重なりの穴を、reviewerが承認の前に見つけた

- **種類**: レビュー指摘
- **観測した事象**: API設計の最初の案に、reviewerが送り直し・重なりの穴を5件指摘した。2回目の解散・退会が202にならない、上限1回の招待リンクの送り直しが失敗になる、セトリの送り直しが`stale_version`になる、写真付きの下書きの送り直しが`id_conflict`になる、2本の作成が重なると500になる、の5件。どれも承認の前に直し、Codexは指摘なしだった
- **発生回数**: このタスク内1回（指摘5件） / 累計5回（工程3で2回、工程4で1回、同じ日のPR #15の通知の設計の見直しで1回）
- **対象タスク**: design-step5-api-design
- **原因仮説**: IMP-2026-001で`ask-questions`の進め方3に足した1文は「問いを書く前」に流れを書き出す手順で、問いの答えを受けて設計書を書く段では通らなかった。今回の穴は、問いでなく設計書の本文で生まれた
- **改善案**: IMP-2026-001の効果の判定に使う。足す先を`create-design-document`にも広げるかは、工程6で同じ型が出るかを見てから決める
- **変更対象**: まだ未定
- **想定される副作用**: なし
- **評価方法**: 工程6で、レビューが送り直し・重なりの穴を何件出すかを数える
- **昇格判定**: IMP-2026-001の再発として数える（新しく起票しない）
