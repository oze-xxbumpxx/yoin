## 観測した事象

### 事象1: 確定したあとのレビューで、穴が10件と2件見つかった

- **種類**: レビュー指摘
- **観測した事象**: 11-06に確定したデータモデルに、Codexの敵対的レビューが10件を指摘した（退会で消す範囲、解散で残すもの、リマインドの時刻と取りこぼし、文脈をまたぐ外部キーなど）。11-10のPR #1では、さらに2件（`sending`のまま止まったリマインドを引き受け直せない、`erasure_jobs`の一意制約で再び抜けられない）を指摘した
- **発生回数**: このタスク内2回
- **対象タスク**: design-step3-data-model
- **原因仮説**: 確定の前に、処理が途中で止まったとき・同じ操作を2回したときの流れを、テーブルごとにたどっていなかった
- **改善案**: データモデルを確定する前に、Codexの敵対的レビューを1回通す
- **変更対象**: （まだ未定）
- **想定される副作用**: 確定までの日数が1日ほど延びる
- **評価方法**: 次の設計の工程で、確定後に出る重大な指摘の件数を数える
- **昇格判定**: Memory留め（昇格せず）。同種の重大指摘は複数あったが、設計の工程は1回目なので再発を見る

- **発生回数**: このタスク内1回

- **原因仮説**: 起動のしかたを決める時点で、Neonが使われていない間は止まるという費用の前提を確かめていなかった
- **改善案**: 定期に動く処理を置くときは、そのとき起きる外部サービスと費用を同じ資料に書く
- **変更対象**: （まだ未定）
- **想定される副作用**: なし
- **評価方法**: 工程6の試算で、設計を戻す変更が出るかを見る
