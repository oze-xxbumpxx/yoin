## 観測した事象

### 事象1: 承認の前のレビューで、デプロイの順番の穴が5件見つかった

- **種類**: レビュー指摘
- **観測した事象**: ADR-0004の案に、Codexの敵対的レビューが5件を指摘した。最初の準備の順番、デプロイを環境ごとに1本ずつ動かす、文脈をまたぐ外部キーをSQLで書く、消すマイグレーションは使わなくした版が動いてから流す、前の版のLambdaが終わるまで待つ、の5件。5件のうち3件は、マイグレーションと前の版のLambdaが同時に動くときの流れだった。直したあとの見直しでは指摘なし
- **発生回数**: このタスク内1回（指摘5件） / 累計3回（工程3で2回）
- **対象タスク**: design-step4-dev-tools、design-step3-data-model
- **原因仮説**: 問いを出す前に、処理が途中で止まったとき・2回流れたとき・前の版と重なったときの流れをたどっていない。工程3と同じ型で、確定前のCodexのレビューが拾っているので、承認後に残った穴は無い
- **改善案**: 処理の順番を決める問い（デプロイ、ジョブ、送信、削除）を書く前に、「途中で止まる・2回流れる・前の版や別の処理と重なる」の3つの流れを論点の記録の前提に書き出す。`ask-questions`か`create-adr`に1文足す
- **変更対象**: Skill（`ask-questions`または`create-adr`。ユーザーが選ぶ）
- **想定される副作用**: 論点の記録が少し長くなる。順番に関係しない問いでは書かなくてよいことにする
- **評価方法**: 工程5と工程6で、Codexの敵対的レビューが順番・重なりの指摘を何件出すかを数える
- **昇格判定**: 同じ型が3回で、昇格の条件を満たす。IMP-2026-001として起票し、直し方を大関さんに出す
