## 観測した事象

### 事象1: 2段の処理が途中で止まったときの続け方を書かなかった

- **種類**: レビュー指摘
- **観測した事象**: Devin Reviewが2か所を指摘した。初期データの手順は、Cognitoのユーザーを作ったあとでDBの行を作る前に止まると、再実行で「すでにあれば何もしない」になり、オーナーが`not_registered`のまま残る。送信結果を`sent`にしたあとで`last_failed_at`を空に戻す前に止まると、届いたのに印が残る。どちらも、続け方と保存の単位を書いて直した
- **発生回数**: このタスク内2回 / 累計2回
- **対象タスク**: first-slice-requirements
- **原因仮説**: 2つの保存先（CognitoとDB、2つの表）にまたがる処理で、全部できたときと何もできていないときだけを考え、片方だけできたときを書かなかった
- **改善案**: 3回になったら、要件のテンプレートの異常系に「2つ以上の保存先を順に書く処理は、途中で止まったときの続け方を書く」を足す
- **変更対象**: まだ未定（`create-requirements-document`のテンプレートの候補）
- **想定される副作用**: 異常系の項目が増える
- **評価方法**: Issue #30の設計書のレビューで、同じ型の指摘が出るかを数える
- **昇格判定**: 留め置きの表に回数2で足す

### 事象2: 初めての人の流れを書かず、すでにいる人の流れだけを書いた

- **種類**: レビュー指摘
- **観測した事象**: ログインをメールのコードだけで書き、Cognitoにアカウントが無い招待客がJWTを得る流れが無かった。Devin Reviewは頻度10・深刻さ7（積70）とした。同じ回に、公演も申込も無い初めての画面の表示も抜けていた
- **発生回数**: このタスク内2回 / 累計2回
- **対象タスク**: first-slice-requirements
- **原因仮説**: 見本の画面がデータの入った状態だけだったので、空の状態と、最初の1回の流れを思い浮かべなかった
- **改善案**: 3回になったら、要件のテンプレートに「初めて使う人の流れと、データが0件の画面」を確かめる行を足す
- **変更対象**: まだ未定
- **想定される副作用**: なし
- **評価方法**: 次のL2 / L3の要件で、同じ型の指摘が出るかを数える
- **昇格判定**: 留め置きの表に回数2で足す

### 事象3: sedで同じ形の行を全部置き換え、別の論点の決定を書き換えた

- **種類**: 失敗
- **観測した事象**: 論点の記録の「- 決定: B」を直すつもりのsedが、ログインと整理番号の決定の行も書き換えた。`reviewer`が見つけ、両方をBに戻した
- **発生回数**: このタスク内1回 / 累計1回
- **対象タスク**: first-slice-requirements
- **原因仮説**: 置き換える行が1つだけかを確かめずに、行の中身だけで当てた
- **改善案**: 3回になったら検討する。いまは、文章の置き換えはその文字列が1回だけ出ることを確かめてから行う
- **変更対象**: まだ未定
- **想定される副作用**: なし
- **評価方法**: 文書の一括置き換えのたびに数える
- **昇格判定**: Memory留め（昇格せず）

### 事象4: 同じ問いを2つのスレッドで追い、答えの場所が分かりにくくなった

- **種類**: Agent間の認識不一致
- **観測した事象**: 券の文字の色は前のスレッドの判断のカードで聞き、要件定義書のスレッドは回答待ちとして追っていた。大関さんはPR #29に自分でコミットを足して答え、マージした。どちらのスレッドも、答えが入ったことをすぐには分からなかった
- **発生回数**: このタスク内1回 / 累計2回（工程4の「同じ工程の問いを、2つのスレッドが別々に出す」と同じ型）
- **対象タスク**: first-slice-requirements、design-step4-dev-tools
- **原因仮説**: 問いを出したスレッドと、その答えを文書に写すスレッドが分かれた
- **改善案**: 3回になったら検討する
- **変更対象**: まだ未定
- **想定される副作用**: なし
- **評価方法**: スレッドをまたぐ問いのたびに数える
- **昇格判定**: 留め置きの表の回数を2にする
